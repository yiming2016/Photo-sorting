### 三、确认并修复的真实缺陷（v195）

**根因**：`Timeline.insert_place()` 只顺延「起点 >= 落点」的同轨片段。落点压在
已有片段 A **内部**时，A 的起点更早、不会被推，松手就变成 A 与 D 同轨重叠 ——
违反 `clips.py` 模块头写明的不变量「同一条轨上不许重叠」，也违反用户定的
「不裁不覆盖」。复现：A[0,10]、B[10,15]、D(dur=2) 落点 3 → 插入后
A[0,10] 与 D[3,5] 重叠 2 秒。

**修法**（`core/clips.py` / `ui/timeline.py`，共 +30/−4）：
- 新增 `Timeline.insert_point(track, start, ignore)`：落点压在片段内部时，
  **就近对齐到该片段的起点或终点**（等距取起点）；本来就在边界/空隙上的
  落点原样返回，v194 既有行为一字不变。
- `insert_place()` 先过 `insert_point()` 再顺延，`skip` 仍按 `id()` 组织。
- `TimelineWidget.mouseMoveEvent` 的 `_insert_ind` 虚线也调同一个函数，
  预览位置与松手落地一致（否则会出现「线在 A 中间，松手 D 跳到 A 前面」）。

**验证**：新增 `out/repro/verify_v195.py` **21 项全过**（数据层 8 组边界：
压内部靠近首/尾、A/B 边界、轨首、轨尾之后、空隙、其它轨、磁吸、越界轨；
外加真实离屏 press/move/release 拖动验证虚线与落位一致且无重叠），
纳入 `_run_all.py`。全量回归 `_run_all_v195.log`：v195 21/0、v194 68/0、
v193 71/0、v192 60/0、v191 51/0，只剩 6 个长期既有 NG。`compileall` 通过。

**发现的真实缺陷（可复现）**：`fields.parse_dt()` 拿 exiftool 输出的时区后缀
直接构造 `timezone()`，且构造在 `try` 之外、不校验范围。
- `+99:99` / `+24:00` → `ValueError: offset must be ... between -24h and 24h`；
  `scanner.py:99` 的 `photos.sort(key=sort_dt)` 只有 `try/finally` 没有 except，
  线程里冒泡后 `finished_scan` 不发 → **一个坏文件让整个文件夹加载不出来**，
  --windowed 下还没有 stderr 可看。`taken_dt()` / `synthetic_display()` /
  分组 / 时间规划 / delegate 绘制全部走同一函数。
- `+08:99` 不抛异常，却被算成 +9h39m → `sort_dt()` 从 09:07 变成 07:28，
  **时间显示与写回静默偏 1 小时 39 分**。
- 修法：校验 `hh<=23 && mm<=59`，非法时区当「没写时区」(tz=None)，日期时间
  主体保留（比整条丢弃、回退文件名更贴合「EXIF 本地时间不带时区」口径）；
  整个解析并入 `try (ValueError, OverflowError, IndexError)` 兜底。

`best`，参数形同虚设。两处拖边对齐关键帧的调用都没传它，所以**当时无实际
影响**；用户确认按「超出间距返回 None」补齐（默认 1e9 行为一字不变）。
