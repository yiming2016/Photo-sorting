# 「统一」模块 · 业务定位与参数充分性评估

> 调查缓存（写于 v241 时点，2026-11-19）。目的：其他 workbuddy 遇到「统一是做什么的 / 这几个参数够不够对不对」时直接读本文件，避免重复通读 normalize.py / norm_page.py / grouping.py / probe.py 全链路。
> 本报告只读调查，未改任何代码、未升版本。

## 1. 一句话定位
第三大形态（排序 → 合并 → 统一）。**本质是「合并」的前置工序**：合并要求一批视频规格完全一致才能无损拼接；「统一」负责把"能靠转码抹平的差异"抹平、生成规格一致的工作副本，"抹不平的差异"则分组隔离。原文件、EXIF/XMP/时间写入一律不动。

- 输入：主列表里勾选的视频（与合并页同一批）。
- 输出：`_photosort_norm/`（或用户自定义输出目录）下的统一规格副本，带参数指纹，源文件变化自动重建。
- 入口文案（顶栏 tooltip）：「把视频统一成同一套兼容规格，生成工作副本」。

## 2. 它统一了什么（两层，关键）
判定基准是 `grouping.DEFAULT_FIELD_LEVELS` 里 13 个 fatal（必须一致）维度；`normalize._FIXABLE` 与之对齐。

**A. 转码强制抹平（用户不用管，代码自动归一）**
视频编码→H.265、像素格式、位深、编码档次(profile)、旋转烘进画面、扫描方式→逐行、流结构→只留 1 视频+1 音频、音频编码→AAC、采样率→48kHz、采样格式→fltp、声道数（整批判定：全单声道→1，否则→2）、时间基→1/90000、编码等级(level，按分辨率+帧率确定性算)。
→ 共 13 个 `_FIXABLE` 维度。

**B. 转码抹不平 → 分组隔离（不改画面，只分组）**
分辨率(width/height)、帧率(r_frame_rate)、HDR 传输、色彩范围/空间/三原色、像素宽高比。
→ 这些在 `_group_key` 里分组；不同规格分成不同组，**组间不能拼**。这是刻意的产品取舍：改画面=整条重渲染，用户护栏明确不做。

## 3. 4 个可调参数（顶栏参数条）
| 参数 | 选项 | 颜色标注 | 真实作用 / 是否影响拼接 |
|---|---|---|---|
| 视频编码 | H.265 Main 8bit(兼容) / Main10 10bit(高质量) | 红(必须一致) | 决定 编码+位深+像素格式+档次；**唯一真正决定能否拼接的用户可调项** |
| 音频 | AAC-LC 128/192/256k · 48kHz | 红(必须一致) | 实际只调**码率**；编码/采样率/采样格式/声道/流结构都是代码写死自动统一的，码率不同并不影响无损拼接 |
| 关键帧间隔 | 1/2/4 秒（2 秒标注"推荐"） | 橙(建议一致) | 影响拖动定位/随机访问，不进拼接判定 |
| 码率质量 | 18(高质量)/20(均衡)/23(省空间) | 灰(参考) | 纯画质/体积取舍，不进拼接判定 |

常量来源：`normalize.CODEC_LABELS` / `CRF_CHOICES=(18,20,23)` / `KEYINT_CHOICES=(1,2,4)`；音频档位写死在 UI 的 (128,192,256)。

## 4. 参数够不够 / 对不对（核心结论）

### 够不够
- **就"把视频统一到能无损拼接"这个目标：够。** 13 个致命维度里，转码能改的 13 项全部自动归一；改不了的（分辨率/帧率/HDR/色彩）靠分组隔离。参数条不需要覆盖所有致命维度——大部分是自动处理的。
- **就"用户控制力"：有边界。** 分辨率/帧率/HDR 不让选也不让转（改画面=整条重渲染，护栏禁止）。所以不同分辨率/帧率的素材，统一后仍分在不同组、依然拼不成一条。这是能力边界，不是缺陷。

### 对不对（几处口径问题，均非 bug）
1. **"音频"标红(必须一致)语义偏了**：它只调码率，码率不同**不影响**无损拼接；真正致命的音频编码(AAC)/采样率(48k)/采样格式/声道/流结构全是自动写死的。标红会误导用户以为码率不一致就拼不上。这是从"音频编码必须统一"沿用下来的旧口径。
2. 关键帧(橙)、码率质量(灰)是画质/体积参数、不进拼接判定，标注合理。
3. "视频编码"标红正确——唯一真正影响拼接的用户项。
4. 参数值有白名单校验：codec 必须 in CODEC_LABELS、crf in CRF_CHOICES、keyint in KEYINT_CHOICES、audio 限 128/192/256；非法值回落默认，稳。
5. **单一来源正确**：生成副本和解析副本都用 `normalize_profile_current`（v217 修），不会"转完解析对不上白转回退默认档"。
6. 判定链路已被系统修复过：v217 档位单一来源、v219 fatal 清单对齐（补声道/多音轨/HDR 三处漏项）、v222 转码中防写碰撞。

### 如需增强的方向（供用户决策，均未做）
- 想"任何视频都能拼成一条" → 必须增加分辨率/帧率/HDR 的重渲染转码，违反现有护栏（画面不动），需用户明确授权后再议。
- 觉得"音频标红误导" → 可把音频降为橙/灰，或文案改为「音频码率(音质)」并注明编码/采样率自动统一。属小改动，需用户点头。
- 想增强控制力 → 可加"目标位深/目标帧率"等选项，但同样触及重渲染边界。
