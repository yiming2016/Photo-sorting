## 修复：添加照片弹窗顶部行被纵向撑高 294px（面包屑改造的副作用）

**现象**（用户截图）：弹窗外观看不出弹窗，顶部那一行（←/→ + 路径 + 显示方式）变成一个高约 300px 的大白框，路径文字在框里垂直居中，下面文件区被压扁。

**根因**：`root`(QVBoxLayout) 里 top/mid 两个子布局的 stretch 都是 0，而 QBoxLayout 在"没有任何 stretch"时会把富余高度分给**能增长**的子项。
- 改造前顶部行放的是 `QLineEdit`（纵向 sizePolicy = **Fixed**）⇒ 整个 top 不可增长 ⇒ 富余全给 mid（正常）。
- 改成 `_BreadcrumbBar(QWidget)` 后，普通 QWidget 默认纵向 **Preferred（含 GrowFlag）** ⇒ top 变成"可增长" ⇒ 与 mid 平分富余高度。
- 实测（offscreen）：dialog 1000×660，内容高 636 → top **294** / mid **294** / bottom 32，正好三块。面包屑自身 780×294（应为 30）。

**修法**（`app/ui/picker_dialog.py`，commit `8829dab`）：
- `_BreadcrumbBar.__init__`：`self.setSizePolicy(Preferred, Fixed)` + `self._stack.setSizePolicy(Preferred, Fixed)`（高度按内容定，不参与纵向拉伸）。
- `root.addLayout(top, 0)` / `root.addLayout(mid, 1)`：显式指定富余高度归中部。
- 修复后实测：breadcrumb 30（原 294）、nav_tree/main stack 556（原 294）、切进/切出编辑态高度恒为 30 不跳变。

**★ 可复用的排查手段**：这次 offscreen 下**成功**测了完整 `PickerDialog`（此前记录"会卡死"是误判）。
可行写法：`os.environ["QT_QPA_PLATFORM"]="offscreen"` → `QApplication([])` → `theme.apply(app)` → `PickerDialog()` → `d.resize(1000,660); d.show()` → 循环 `app.processEvents()` → `dump()` 打印每个控件 `height()/sizeHint()/sizePolicy()` → `app.quit()`，用 `head -40` 收尾即可，不卡。
定位"哪个控件撑高了布局"时，直接 dump 各控件真实 height + sizePolicy 是**最快**的手段（比肉眼猜 QSS 快）。

**提交**：`8829dab`。

## 修复"选中纯子文件夹的文件夹 + 点添加 → 无声失败"（真正根因）

**用户澄清**：不是"点进 B 看右侧"，而是"**选中 B 这个文件夹项 → 点底部「添加」按钮**"。B 里只有子文件夹、没有裸露文件，结果主列表什么都没进来。

**真正根因**（`app/ui/main_window.py` 的 `pick_open`）：
- 选中 B(文件夹)→添加 → `folders=[B]`、`files=[]`，`recursive = 含子文件夹开关.isChecked()`。
- 若**没勾「含子文件夹」**，`collect_files(B, False)` 只取 B 里"裸露文件"= 0 个。
- 原 `pick_open` 在收集到 0 文件时**直接 `self._scan_files([], accumulate=True)` 走完，无任何提示**；而 `open_folder`（拖文件夹那条）是有"这个文件夹里没有找到图片或视频"提示的。所以用户点添加后主列表空着、弹窗关掉，像程序坏了一样。

**修法**（commit `66e1eb6`）：`pick_open` 收集后若 `all_files` 为空：
- 若选了文件夹且 `recursive=False` 且该文件夹**含子文件夹** → 提示"「B」里只有子文件夹、没有直接的图片/视频；如需读入子文件夹里的照片，请勾选上方「含子文件夹」后再添加"。
- 否则通用提示"选中的文件夹里没有找到图片或视频" / "选中的内容里没有找到图片或视频"。
- 提示后 `return`，不再无谓扫描。

**★ 设计背景**：本项目"含子文件夹"是用户**刻意设计的可选开关**（"只处理当前文件夹，可选含子文件夹"），所以默认不递归是对的；本次只补**反馈**，不擅自改递归语义。若用户后续想"选中这种纯子文件夹的文件夹就自动递归"，再单独加开关。

**验证**：打包成功 → 扁平部署 → `软件/照片排序台.exe` 实启存活（PID 29996）。逻辑为纯新增分支，原有正常场景不受影响。

## 新增：添加弹窗在“含子文件夹”未勾选且选中文件夹无内容时弹窗提示（并留住对话框）

**用户要求**：未勾选「含子文件夹」时，选中添加的文件夹若不会显示任何内容，需要弹窗提示。

**改动**（commit `d47616e`）：
- `picker_dialog._on_accept`：收集 folders/files 后，若 `folders 非空且 files 为空`，读取弹窗内 `recursive_check` 状态，用新增静态方法 `_folder_yields_content(folder, recursive)`（按递归设置快速判定文件夹是否含图片/视频，找到第一个即返回）筛出“空文件夹”。
  - 仅当**所有**选中文件夹都为空才拦截（至少一个有内容就正常添加，空文件夹静默跳过）。
  - 空文件夹且**未勾选含子文件夹且其中有子目录** → 弹窗「「X」里只有子文件夹，没有直接的图片或视频。如需读入子文件夹里的照片，请勾选下方「含子文件夹」后再点“添加”。」
  - 其余空情况 → 弹窗「在「X」里没有找到图片或视频。」
  - **关键**：拦截时 `return` 不调用 `accept()`，**对话框保持打开**，用户勾选「含子文件夹」后可立即重试。
- `main_window.pick_open`：原“状态栏静默提示”改为 `QMessageBox.information` 兜底弹窗，覆盖残留空结果（如选中的都是非媒体文件）。因 _on_accept 已拦截文件夹落空场景，此处实际只兜底 files-only 非媒体等少数情况。

**判定标准说明**：与 `scanner.collect_files` 一致——只认 `kind_of != "other"`（图片/视频），非递归只看裸露文件、递归才下钻子目录、忽略以 `.` 开头的隐藏项。
