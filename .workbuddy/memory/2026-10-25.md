## v95（按用户清单核对分档：旋转/扫描提为必须一致 + 流结构判定）

### 背景
用户给了一份「必须一致 / 建议一致 / 仅供参考」的完整清单要求核对事实（覆盖
视频/音频/HDR/时间基/旋转/流结构等）。核对结论 + AskUserQuestion 4 项确认后实施。

### 核对结论（给用户的）
1. **用户清单 1 处放错档**：色彩传输特性(HDR bt709/smpte2084)被放到「建议一致」，
   实际 SDR/HDR 混拼画面必然发灰/过曝 → 必须一致。程序原本就是 fatal，未改。
2. **时间基偏严**：concat demuxer 会自动换算时间刻度，通常不花屏不不同步；
   不同设备时间基常不同（手机 1/15360 vs 相机 1/90000），提为必须会误判。
   用户采纳推荐 → 保持 warn。
3. **「音频时间基」不用单独列**：= 1÷采样率，采样率一致它必一致，冗余。
4. 旋转（不会花屏只是方向错）、扫描方式（隔行/逐行混拼会花屏）→ 用户确认都提为 fatal。
5. 流数量 → 升级为流结构（用户确认）：数量相同但结构不同（1视频+1音频 vs 2视频）也要拦住。
6. 小提示（未实施）：帧率用 r_frame_rate 对 VFR 不准，可改 avg_frame_rate。

### 改动
- `FIELD_LEVELS`：rotation / field_order → **fatal**；「流数量」改名「流结构」。
- `signature()` 同步加 rotation、field_order、流结构 —— **不加就会重现 v94 的
  「分组判可无损而对比标红」矛盾**。归一化函数：
  - `_norm_rotation`: None/0/360/-360 → 0（无旋转元数据 = 不旋转）；
  - `_norm_field_order`: ""/unknown/progressive → progressive，tt/bb/tb/bt 保留；
  - `_norm_stream_layout`: (video_streams, audio_streams) 元组，老 spec 回退 nb_streams。
- `probe.py` 采集 `video_streams`/`audio_streams` 条数（字幕/data 流不参与——不影响画面声音）。
- `field_value("nb_streams")` → `"1视频+1音频"`（无结构字段回退 "2流"）；
  四处（标题/对比/右侧/属性）统一。
- 「都是逐行」不占对比行（与旋转 0° 不占行对称）：`compare_rows` + 属性窗口 `_update_spec_rows` 同步。
- time_base 保持 warn。

### 验证
- 命令行断言：rotation None/0 同签名、0/90 异；field_order None/progressive 同、/tt 异；
  流结构 (1,1)/(2,0) 异、回退一致；分档 rotation/field_order=fatal、time_base=warn；
  展示 "1视频+1音频"；fatal 档 13 项。
- 截图 `out/v95_compare.png`：流结构/旋转/扫描方式三行冲突全在红色「必须一致」档。
- 发布：__build__ 94→95，exe 标题 `照片排序台 v95`（PID 37700）。

## v99（参数分档弹窗改版：带色下拉/排序切换/同档拖拽/顺序持久化）

### 背景
用户验收 v98 的 ⚙ 参数分档弹窗：①「分档」列下拉文字底部有一点被截；②弹窗太短显示不全；
③分档文字要按等级染红/黄/绿（下拉菜单和选中态都要）；④下拉只显示另外两项、不显示已选中的；
⑤点「分档」表头切换 必须一致在前/仅供参考在前 两种排序；⑥两种排序下都可手动排序（不可跨档），
顺序永久保存。

### 改动
- **弹窗加高**：`setMinimumSize(500,640)` + `resize(520,740)`，行高 34→38 —— 文字不再截断。
- **带色下拉 `_LevelCombo`**：只读 QComboBox（1 个占位 item），选中态用内联 QSS `color` +
  palette(Text/ButtonText) 双保险上色；`showPopup()` 重载为自绘 QMenu（QWidgetAction+`_MenuLabel`），
  **只列另外两档**、各带色（fatal=DANGER 红 / warn=WARN 黄 / None=OK 绿），带悬浮高亮。
- **表头切换**：`horizontalHeader().sectionClicked` 接 col==1，`_group_desc` 翻转后
  `_sorted_by_group(rows, desc)` 稳定分组重排（组内相对顺序不变）。
- **同档拖拽 `_LevelsTable`**：DragDrop 模式 + `startDrag` 记 `currentRow`，`dragEnter/Move`
  调 super 后 acceptProposedAction（让 Qt 算落点指示），`dropEvent` **不调 super**——
  算目标行(indexAt+dropIndicatorPosition)发 `reorderRequested(src,dst)` 信号，弹窗自己改
  `self._rows` 再整表重建（不依赖 Qt 内部 move，避免 cellWidget 搬移丢控件）。
  `_reorder` 里 `_block_bounds` 求同档连续区间 [lo,hi)，dst 夹回 [lo,hi) —— **跨档拖拽自动变成

  成为唯一入口（order 缺的 key 按出厂顺序补尾部），`set_field_levels` 改为保持现有顺序的兼容壳；

  `_rebuild` 初始 rows 直接读 `grouping.FIELD_LEVELS`（已含用户顺序），不再从 DEFAULT 重排。

- `_LevelsTable(len(rows), 2)` —— 子类 `__init__` 必须接 (rows, columns, parent) 再传 super，
  否则 TypeError（第一版只接 parent）。
- QComboBox 原生 popup 无法"隐藏当前项"+按 item 上色（QSS `::item:hover` 强制盖色），
  直接换自绘 QMenu 最稳。

## v100（命名变量面板不抢焦点——弹出时仍可手动输入）

### 背景
用户反馈：TemplateEdit「点输入框弹菜单」和「手动打字」互相打架——QMenu.popup() 会
grabKeyboard 抢焦点，菜单一弹光标就消失、打字无效。用户明确要求**同时存在**，
拒绝「单独按钮/右键」方案。

### 改动
- **弹出物换掉**：不再用 QMenu.popup（grabKeyboard 是罪魁），自绘 `_VarPanel(QWidget)`：
  `Qt.Popup | FramelessWindowHint | WindowStaysOnTopHint | WindowDoesNotAcceptFocus`
  + `WA_ShowWithoutActivating` + 面板和所有子控件 `setFocusPolicy(NoFocus)`。
  效果：弹出后焦点仍留在输入框（光标在、可打字），点面板外自动收起
  （Qt.Popup 只抓鼠标不抓键盘；QMenu 才显式 grabKeyboard）。
  这正是 QCompleter 弹层「边打字边出建议」的同款机制。
- **布局**：五类分节灰标题 + 变量小按钮（QGridLayout 4 列、蓝色文字、tooltip=说明），
  点按钮 `insert(token)` 后 `panel.hide()`；位置=输入框左下角正下方。
- 验证坑：测试脚本里 `QFontDatabase.addApplicationFont` 放在 QApplication **之前**会
  segfault（p1→p2 断点定位），必须先建 QApplication 再加字体——和应用代码无关。

### 离屏可验证/不可验证
- ✅ 面板可见、`app.focusWidget() is not panel`、insert/pick 正常、截图正常。
- ❌ 真实键盘焦点行为离屏测不了（WA_DontShowOnScreen 下 setFocus 不生效），
  只能靠 Qt.Popup 语义保证，真机需用户点验。

### 背景
用户验收 v100 提出：①变量面板按钮全是 `%fn`/`%ia`，用户看不懂，要**全改中文**（输入框里的

### 改动
- **naming.CATEGORIES 改三元组** `(token, 中文短名, 说明)`：面板按钮只显示中文短名，
  符号只出现在插入输入框之后；说明放 tooltip（`说明　（插入 %xx）`）。38 项全中文。
- **常用类扩成 8 项并置顶**（原名/规格/序号/日期/时间/年/月/日），面板矮到 180px 时

- **`_VarPanel` 从独立窗口改为主窗口内普通子控件**（v100 的 `Qt.Popup` 方案仍失败）：
  · 根因：Windows 上任何独立窗口显示即成为**活动窗口**，主窗口失活 → QLineEdit 光标消失、
    键盘打不进；`WindowDoesNotAcceptFocus`/`WA_ShowWithoutActivating` 都救不了。
  · 子控件没有自己的焦点 → 点按钮时光标仍在输入框，键盘与点选真正并存。
  · 点外面收起：app 级 `eventFilter`（`widgetAt(全局坐标)` 判落点是否在面板/输入框内）。
  · 内容比窗口高 → 套 `QScrollArea`（滚动条 `NoFocus`），`fit(max_h)` 按可用空间定尺寸。
  · **定位铁律**：贴输入框正下方，宁可变矮出滚动条，也绝不许滑上去盖住正在打的字；
    下方 <150px 才翻上方。
- **dt 缺失保护**：`_TIME_TOKENS` 在 dt=None 时返回空串（以前 `%y` 原样写进文件名）；
  命名时间统一 `_photo_dt()`（`sort_dt()` 兜底文件时间，再退 `taken_dt()`）。
- 右键菜单 `移动到合并文件夹（N 段）…` → `N个移动到…`。
- 移动弹窗删掉「原位置的文件会被移走，列表里的路径自动更新。」
- 警告改「所选文件无法无损合并」，其中「无损」两字 `T.DANGER` 红字，原「注意：…」删。

## v110（真正根治：无效色刷 setBackground(QColor()) 让项变黑）

### 背景
用户验收 v109 仍说「依旧发黑」。这次**复现出了真凶**：离屏测试一直不黑是因为没应用全局

- 三个处理器全部改用 `_ROLE_HL`：

  - `_on_preview_item_entered` → `setData(_ROLE_HL, 'selected' if 选中 else 'hover')`
  - `_on_preview_double_click` → 旧选中 `setData(_ROLE_HL, None)`，新选中 `'selected'`
- 代理仍先画不透明 `T.SURFACE` 底 + 清状态位 + 清 backgroundBrush，双保险。

### 验证（`repro_black_v109.py` 应用主题 + 真 dialog）

- **铁律（永久）**
- **QListWidget 项不要用 `setBackground(QColor())`（无效色）清除/设背景**：无效色刷带主题会变黑。

## v112（框选滚动不丢失 + 顶栏「单独」板块 + 弹窗改名）

### 1) 框选后滚动页面丢失（grouplist.py）
- **根因**：框选矩形按**屏幕坐标**记（`_rubber_origin` + 当前鼠标点）。滚动页面后内容在动、
  矩形不动；紧接着任何一次鼠标移动（哪怕 1px）都会用 `ClearAndSelect` 把"现在位于矩形下的"
  换上去，之前框选的那批被整批冲掉。实测：`['53','49','45','46']` → `['42','39','37','34']`。
- **修法（内容坐标锚定）**：
  - `_scroll_offset()` / `_to_viewport()` 两个换算助手；矩形两角都记**内容坐标**。
  - 终点 `_rubber_end_c` 只按**鼠标位移**递增（`pos - _rubber_last_pos`），不按
    "屏幕坐标+滚动偏移"重算 —— 否则滚动一次后挪 1px，终点会跟着滚动量跳一大截（矩形翻转/塌缩）。
  - 滚动时 `_on_scrolled` 重算 Marquee 几何（= 内容矩形 - 偏移，视觉上跟着内容走）并重选一次
    （内容矩形没变 → 选中集合不变）。
  - `mousePressEvent` 顶部加"收尸"：异常残留的 Marquee 先清掉，防止旧框挂屏 + 下次拖动用陈旧原点。
- **坑**：`QRect(x1,y1,x2,y2)` 四参构造是 (x,y,**宽,高**)不是角点；要用 `QRect(QPoint,QPoint)`。
  另：原点不能从 `_rubber_rect.left()/top()` 反推（normalize 后左上角可能变成终点）→ 必须单独存。
- **验证**（`out/repro/test_marquee_v112.py`，9 项全过）：普通框选与手动矩形命中一致；
  框选后滚动不变；**按住不放→滚动→挪1px→松手不变**（原来这条必丢）；滚动时矩形几何=内容矩形-偏移；
  Ctrl 加选两批都在；残留 Marquee 被清理。

## v113（框选不跟着滚轮走 —— 改「视图自绘」，砍掉子控件浮框）

### 用户反馈
「框选一些文件后，长按鼠标左键，滚动滚轮，框选的框没有跟随滚轮滚动」

### 排查过程（重要教训）
- 离屏用合成事件怎么测都复现不了（框确实跟着滚轮走了）；套主题 + 高 DPI(1.5) + 真弹窗也一样。
- 从 exe 的 PyInstaller CArchive/PYZ 里把 `app.ui.grouplist` 解出来校验（见
  `out/repro/check_exe_code.py`），确认 v112 内容坐标锚定代码**确实在**用户跑的 exe 里。
- 结论：不是"代码没打进去"，而是**架构脆弱** —— 框是一个盖在视口上的 QRubberBand 子控件，
  必须靠每条滚动路径（scrollbar valueChanged）手动 `setGeometry` 搬位置；真实系统派发
  （spontaneous 滚轮事件、拖动中的隐式鼠标抓取、指针正压在框上）与合成事件路径不同，
  任何一环没搬到位，框就停在屏幕原处 → 用户看到"框不跟着滚轮滚动"。

### 修法（v113，结构性）
- **框选矩形不再做成子控件**，改由 `GroupView.paintEvent` 在 `super().paintEvent()` 之后
  直接画在 viewport 上：矩形仍按**内容坐标**存，绘制时才减滚动偏移。
  → 不管页面是被滚轮 / 滚动条拖动 / 自动滚动 / 键盘翻页 / scrollTo 哪一种方式挪动的，
  重绘时框都自动出现在同一个内容位置上，**永远跟着内容走**，不依赖任何滚动路径。
- `_rubber_on` 布尔代替 `_rubber` 控件引用；press/move/release 里改为 `viewport().update()`。
- `_on_scrolled` 只负责 `update()` + 重算选中（框的位置由绘制时换算，天然正确）。
- `wheelEvent` 里拉框状态下补一次 `update()` + `_select_in_rect()` 双保险。
- 附带好处：不再有"子控件挂屏/吃事件/Z 序"这一类问题； Marquee 类仍留给 picker 用。

  旧位置无框(0.00) → 多次滚动仍锚定/被裁剪 → 松手消失、选中保留 → 普通框选仍生效。
