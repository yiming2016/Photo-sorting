C 盘 3.7GB 一直没释放。`dist/` 里留 v26 + v27（保留一级可回退）。

### 本次执行

  里面的 jpg/mp4/x3f 全部来自 `exiftool_files/t/images/`（exiftool 自带测试图），无用户照片。
- 无进程占用；当时没有照片排序台实例在运行。
- 用 `robocopy /MOVE /E` 把暂存目录**跨盘搬到 D 盘**当可还原备份：
  `D:\_照片排序台_旧版本备份_2026-09-05`（文件数 29474 对齐，3.55GB）。
- 结果：C 盘可用 365.4 → 369 GB；D 盘 594.8 → 591.1 GB。

- 备份仍在 D 盘，等用户确认 v27 无问题后可自行删除。
- `build/`（PyInstaller 中间缓存）270MB 未动 —— 删了下次打包要重新全量分析，留着。

### 可复用经验（重要）
1. **本环境删大目录的两道坎**：
   - `Add-Type`（动态编译加载 .NET）被安全策略直接拦截 → 没法用
     `Microsoft.VisualBasic.FileIO.FileSystem::DeleteDirectory(...SendToRecycleBin)` 走回收站。
     注意：即使命令里没写 Add-Type，只要引用 `[Microsoft.VisualBasic...]` 也会被拦。
   - safe-delete hook（genie-trash）会拦 `rm`，所以之前那轮只能"搬到暂存目录"而不是删。
2. **可行方案（推荐）**：`robocopy 源 目标 /MOVE /E /R:2 /W:2` 跨盘搬到其他盘当备份。
   既释放了系统盘空间，又保留了可还原副本，比回收站更稳（回收站有容量配额，3.7GB 可能被静默永久删除）。
3. **robocopy 退出码 0-7 都算成功**（1 = 成功复制了文件），用它判失败会误报；
   任务状态显示 failed 时先看 stdout 的实际退出码再下结论。
4. 清理前务必先做"有没有个人文件混入"的核验：
   `find 目录 -type f \( -iname "*.jpg" -o ... \) | grep -v exiftool_files`。

## v28 — 修复三个 v27 已知问题

### Task #11（修 ①）跨组拖动不再产生重复分组标题
- 现象：把 2023 的照片拖到 2024 后，列表里出现 `2023 → 2024 → 2023` 三个连续标题
- 根因：`PhotoModel._segment_keys()` 按每张照片自己的日期算分组键；被拖走的照片日期不变，在新位置又起一个新段
- 修复：给 `Photo` 加一个 `group_override: tuple | None` 字段；`_segment_keys()` 优先用 override；`move_rows()` 在拖动时把被拖照片的 override 设为落点附近那张图的 key（让它们在新位置"融入"周围分组，不再单独起段）
- 清理时机：`sort_photos()`、`reverse_photos()`、`_on_write_finished()`（写入完成后日期已落到磁盘，分组应该回到日期驱动）

### Task #12（修 ②）HEIC/RAW/视频在添加对话框能显示缩略图
- 现象：v27 之前 `_ThumbDelegate._pixmap` 只走 `QImageReader`，遇到 HEIC/RAW/MP4 直接返回 None，对话框里只能显示系统图标
- 修复：加 `_load_heavy()`，复用主程序 `app.core.thumbs` 的现有管线：
  - 命中磁盘缓存（`cache_dir/cache_key`）→ 1ms 以内
  - 视频 → `thumbs._decode_with_ffmpeg`（subprocess + `-ss 0.5 -frames:v 1`）
  - 图片（含 HEIC）→ `thumbs._decode_with_pillow`（pillow_heif 已注册过 opener）
- 缓存里统一存 360px jpeg，paint 时再按 `self.thumb` 缩放到 96/48/32/16

### Task #13（修 ③）拖到分组标题按上下半区精确落点
- 现象：v27 之前拖到任何 HeaderRow 都只能"落在分组之前"
- 修复：在 `grouplist._live_move` 的 HeaderRow 分支加 `pos.y() < visualRect.center().y()` 判断：
  - 上半 → 落上一张照片之后（无上一张则兜底到组内第一张之前）
  - 下半 → 落组内第一张之前（无下一张则兜底到上一张照片之后）

### 调试路上踩的两个坑
1. **`from .thumbs` 是相对导入到 `app.ui.thumbs`，不存在** → `except` 吞掉，永远返回 None。正确写法是 `from ..core.thumbs import ...`。第一次写错时所有"重负载"路径都 0ms 返回 None，debug 时加 monkey-patch 的 loud() 版本才暴露问题。

## v30 — 修复"添加"选择框仅在'详细信息'视图显示文件的 bug

### 现象（用户反馈）
- 点「添加」进选择框后，**只有"详细信息"视图能看到文件**；
  超大图标/大图标/中等图标/小图标/列表 等其它视图全部空白。

### 根因（隐蔽的 paint-time 异常）
- `app/ui/picker_dialog.py` 的 `_ThumbDelegate.paint()` 在画缩略图锚点时用了 `QPoint(0, 0)`，
  但文件顶部的 `from PySide6.QtCore import (...)` 元组里**漏了 `QPoint`**。
- 每个条目 paint 时抛 `NameError: name 'QPoint' is not defined`。
- **PySide6 会在委托 paint 抛异常时静默捕获并只记录到 stderr**（不冒泡到主线程），
  导致该条目被画成空白 —— 用自绘 `_ThumbDelegate` 的 list/tree/icon 视图全部空白；
  **只有"详细信息"用默认 delegate（QTreeView）不经过 `_ThumbDelegate`，所以幸存**。

### 为什么离屏测试没抓到
- 之前的探测脚本只查 `model.rowCount()`（模型层），与 paint 无关，永远是好的。
- 只有触发**实际 paint**（`dlg.grab()` 渲染到 PNG）才会让 paint-time 异常浮出水面。
- 因此排查 picker 视图"显示不出来"这类问题时，**必须 `dlg.grab()`**，光查 rowCount 抓不到。

### 修复
- 在 `picker_dialog.py` 的 `PySide6.QtCore` import 元组补上 `QPoint`。

### 验证（`_probe_render.py`，已删临时脚本与 `_v29_render/`）
- 用 `dlg.grab()` 强制 paint → 6 种视图全部渲染成功：
  超大图标/大图标/中等图标/小图标 显示 3 张彩色缩略图，列表 3 行，详细信息文字列。
- 打包 `照片排序台_v30` → Start-Process → PID 18512。

## v33 — 自动间隔对话框 修正三处（用户："直接执行"）

### 1. 起始时间去掉外框，修正分隔符位置
- 问题：v32 的 `_DateTimeSegments` 每个段仍是带框的 QSpinBox（`border: 1px solid BORDER`），
  且 5 个分隔符 `- -  : :` 被**分两个循环**添加 → 全挤到了 6 个数字**末尾**，位置全错。
- 修复：
  - `_DT_SEGMENT_QSS` 去掉 `border` / `background` / `border-radius`，只剩
    `selection-background-color: ACCENT; selection-color: #FFFFFF; padding: 1px 2px;`
    → 6 个段变成**裸数字**，无外框。
  - 分隔符插入改成**与 6 个数字在同一个循环里交替**：`[年]-[月]-[日][空格][时]:[分]:[秒]`。
    第 3 个分隔符是一个空格（不是两个），`setMinimumWidth(3)`；其余 `-`/`:` 紧凑 `setMinimumWidth(2)`。
- 渲染确认：`2026 - 09 - 06  00 : 48 : 58`，数字无框、分隔符位置正确、聚焦段整段蓝选白字。
- 教训：**多个控件 + 分隔符要"交替"布局时，必须在同一个循环里按顺序 addWidget，
  不能先加完所有控件再加所有分隔符**，否则分隔符全挤到末尾。

### 2. 间隔下拉框移到数值后面，数值框不带单位
- 布局从 `[间隔][单位combo][数值spin]` 改为 `[间隔][数值spin][单位combo]`。
- `value_spin` **不再 `setSuffix(" 单位")`**（删掉 `_on_unit_changed` 与其 suffix 挂载）——数值框里只有纯数字。
- 单位 `unit_combo` 放到数值右边，`setSizeAdjustPolicy(AdjustToContents)` + `setMaximumWidth(72)`
  防止内容自适应后撑成超长。

### 3. 三个时间下拉显示不全
- 问题：v32 用 `minimumContentsLength(10)` + `AdjustToMinimumContentsLengthWithIcon`，
  Windows 上对 CJK 字符宽度估算偏低 → 最长项"修改时间比拍摄晚 1 秒"只显示到"致"。
- 修复：用 `QFontMetrics(self.sync_combo.font()).horizontalAdvance(最长项)` 精确量出**像素宽度**，
  `setMinimumWidth(量出宽度 + 40)`（+40 是下拉箭头 ~18 + 左右内边距 ~16 + 冗余）。
- 实测：最长项 122px + 40 → 最小宽 162px，切换 cascade 项完整显示"修改时间比拍摄晚 1 秒"。
- 经验：**CJK 文本在 QComboBox 用字符数定宽会偏小，要用 `QFontMetrics.horizontalAdvance` 量像素。**

## v34 — 自动间隔对话框 细节修正（用户："直接执行"）

### 1. "起始时间"/"三个时间"的"间"字被截
- 问题：`lbl_start` / `lbl_sync` 用 `setFixedWidth(64)`，4 字 CJK（起始时间/三个时间）放不下，"间"被截。
- 修复：改为 `setMinimumWidth(72)`，让 label 按文字自适应（不再固定死宽度）。

### 2. 起始时间 6 段间隔太远
- `outer.setSpacing(1)` → `0`（6 段与分隔符完全挨紧）；
  spin 宽度 年段 42→38、其余 32→30；分隔符 `lbl.setMinimumWidth(0)` 删除（靠 spacing=0 贴紧）。
- 渲染确认：`2026 - 09 - 08  00 : 04 : 46` 紧密贴合。

### 3. 单击渲染蓝选、再点击显示竖线精细化输入
- v33 的 `arm_caret` 机制（第 1 个 MouseButtonPress 开 caret）不够直观。
- 改为 `eventFilter` 直接监听 **`MouseButtonDblClick`**：
  - `FocusIn` → `_set_caret_width(0)` + `selectAll()`（单击/进入即整段蓝选）
  - `MouseButtonDblClick` → `_set_caret_width(1)`（双击才显示竖线，进入精细化输入）
  - `FocusOut` → `_set_caret_width(0)`（离开恢复蓝选）
- 即：**单击=蓝选整段、双击=竖线光标精细化输入**，符合用户"单击蓝选，再点击才是竖线"的描述。
- `_set_caret_width()` 静态方法：`spin.findChild(QLineEdit).setProperty("cursorWidth", width)`。

### 4. 间隔单位下拉长度
- 用户要"改 50%"。曾试 `setFixedWidth(20)` —— 但 20px 窄到**单位字完全看不见，只剩箭头**，可用性太差。
- 最终改为 `setSizeAdjustPolicy(AdjustToContents)` + `setMinimumWidth(40)`：
  下拉框**按单位文字自适应**（选"秒"窄、选"分钟"稍宽），始终能看到单位字 + 箭头，又不会超长。
- 教训：**下拉框宽度不能窄到连一个汉字都放不下**——否则单位字消失只剩箭头，
  用户根本不知道选的是什么单位。宁可让它跟随内容自适应 + 设个下限，也别固定过窄。

### 可复用经验（重要）
- **PySide6 委托 paint 抛异常是静默的**：只在 stderr 打印 `Error calling Python override
  of QStyledItemDelegate::paint()...`，界面表现为"条目空白但不崩"。调试要靠强制渲染
  （`dlg.grab()` / 截图）才能抓到，单查模型 rowCount 无效。
- `QPoint` 在 `PySide6.QtCore`，不是 QtGui。—— 写委托 paint 前先核对 QtCore/QtGui 的
  import 是否齐全，凡是用到的几何类一起 import。

## v35 — 自动间隔对话框 4 处 UI 调整（用户："执行，以后不需要我说执行"）

延续 v32~v34 的"自动间隔"对话框打磨，本次按用户 4 条反馈改 `app/ui/dialogs.py`
的 `IntervalDialog` / `_DateTimeSegments`：

### ① 起始时间六段悬浮显示箭头光标
- 现象：鼠标移到"起始时间"的年月日时分秒数字上时，是 I 型文本光标，用户要箭头光标。
- 根因：段是 `_SegSpinBox`（QSpinBox），内置 `QLineEdit` 默认 I-beam 光标。
- 修复：在 `_DateTimeSegments.__init__` 循环里，给 spin 和内置 lineEdit 都
  `setCursor(Qt.ArrowCursor)`（line 109-114）。保留 `_hide_spinbox_cursor` 的"无闪烁竖线"。

### ② 间隔单位下拉宽度改为约 50%
- v34 的 ④ 曾试 50% 但 `setFixedWidth(20)` 窄到单位字消失只剩箭头，于是退回
  `AdjustToContents + setMinimumWidth(40)`。本次用户坚持要 50%，做了一套**自适应 + 下限**方案：
  - 新增 `_resize_unit_combo()`：`QFontMetrics.horizontalAdvance(当前单位文字)` 量出自然宽，
    `setFixedWidth(max(36, int((nat + 22) * 0.5)))`（22 ≈ 箭头+内边距，取一半）。
  - 初始和 `currentIndexChanged` 都调它 → 切到"秒/天/分钟/小时"各按其自身宽度一半显示，
    不会某单位被过度裁切；下限 36px 保证至少看得到一个汉字 + 箭头。
- 权衡：50% 下双字单位（分钟/小时）在框里只露约一个字，但 popup 列表仍显示完整，
  可接受；若用户觉得裁切碍眼，把下限 36 调大即可。

### ③ ⓘ 更靠近"三个时间"文字
- `row2.setSpacing(4)` → `2`；`info_btn` 左边距 `margin: 0 4px 0 -2px` → `... -6px`，

### 打包翻车与修复（重要）
- 第一次 `PyInstaller` 在 COLLECT 阶段 `_rmtree(software\照片排序台)` 抛
  `PermissionError [WinError 5] 拒绝访问 ...\_internal\tools\exiftool_files\lib\auto\Fcntl\Fcntl.xs.dll`。
- 根因：**杀掉主程序（pid 6652）后，它派生的 `exiftool.exe` 子进程成了孤儿**（pid 27144，
  还驻留在 `software\照片排序台\_internal\tools\exiftool.exe`），仍锁着旧 dist 里的 DLL。
  和之前"打包前必须杀旧实例"的坑是同一类——但光 `Stop-Process -Name 照片排序台` 不够，
  **得按模块路径扫出孤儿 exiftool 一起杀**。
- 修复：`Get-Process | Where-Object { $_.Modules | Where-Object { $_.FileName -like '*照片排序台*' -or '*exiftool*' } }`
  找出 pid 27144 → `Stop-Process -Force`。清干净后重跑 PyInstaller 一次成功
  （"Build complete! ... available in: C:\software\Photo sorting\software"）。
- **可复用经验**：每次重建 `software\照片排序台` 前，除杀主程序外，务必扫一遍
  模块路径含 `照片排序台` / `exiftool` 的孤儿进程并杀掉，否则 COLLECT 的 rmtree 必失败。
