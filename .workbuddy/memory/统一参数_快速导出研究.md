# 「统一参数」如何服务于「剪辑快速导出」— 研究缓存

> 研究任务（v241 时点，2026-11-19），**只读、未改任何代码、未升版本**。
> 用户诉求原话：「目的是同意后，剪辑的时候可以快速导出」「现在先不操作」。
> 目的：把"统一参数该怎么调才能利于剪辑快速导出"研究透，等用户同意后再动手。

## 一、核心因果链（已完整贯通，经代码确认）

「统一」不是孤立功能，它是**剪辑秒级无损导出的前置准备**。闭环如下：

1. 用户在「统一」页转码 → 生成规格一致的工作副本（`_photosort_norm/_ns_*.mp4`，H.265/AAC/48k/固定时间基）。
2. 统一完成 `_on_normalize_done` → `merge_specs.pop(path)` 强制重新探测（main_window.py:8077）→ `_start_probe`。
3. 探测 `ProbeWorker` → `probe.probe_ex(path)` **默认 resolve_path=True** → 探测的是副本规格（probe.py:41），写回 `merge_specs[p.path]`。
4. 无损判定 `lossless.evaluate(timeline, self.merge_specs, ...)`（main_window.py:5054）用的是**副本规格** → 规格一致 → 判 `mode="lossless"`。
5. 剪辑导出 `export.py::_src()` 用 `norm_paths.resolve()`（export.py:25-27）→ 喂给 ffmpeg 的也是副本。
6. 无损导出 = 每段 `-c copy` 切出（切点贴关键帧）+ concat demuxer 拼接 → **秒级、零损失**；否则走 `_reencode` 整条 filter_complex 合成（慢、有损）。

→ **探测 / 判定 / 导出三处都走副本，口径一致**，闭环在 v200 就打通了。用户"统一后剪辑快速导出"的路径已经存在，不是缺口。

## 二、决定"能否快速导出"的关键（lossless.evaluate 的 fatal 清单）

剪辑能否走 `-c copy` 秒级路，取决于时间线是否触发 fatal。与"统一"相关的 fatal 只有一条：**`spec` 编码参数不一致**（用 `grouping.signature()` 比 13 个 fatal 维度）。其余 fatal（画面重叠/图片/音量/音频混排/有无音轨混排/纯音频）都与统一参数无关，是剪辑操作本身或素材内容问题。

统一把 13 个 fatal 维度中的 **10 个自动抹平**（编码/位深/像素格式/档次/音频编码/采样率/采样格式/声道/流结构/旋转/扫描/时间基/level 中的可转码项），抹不平的 3 个（分辨率/帧率/HDR）靠分组隔离。

**推论**：只要用户 Uniform 时选同一档、且剪辑只在同一分组内选片 → 规格必一致 → 必能秒级导出。跨组（不同分辨率/帧率/HDR）选片 → 规格不一致 → 判 fatal → 慢路。这一条护栏不允许靠改画面消除。

## 三、关键真相：关键帧密度才是"剪辑快速导出"的真正可调杠杆

统一转码命令（normalize.py:401-408）：
```
keyint = clamp(fps × keyint_sec, 1, 300)
x265 = keyint=N:min-keyint=N:scenecut=0:open-gop=0:repeat-headers=1:level-idc=<名>
```
- `scenecut=0` + 固定 `keyint` = **严格等间距关键帧**，可预测、易下刀。
- `keyint_sec`（可调参数之一，当前 1/2/4 秒，默认 2）直接决定关键帧密度。
- 无损导出的入点会"贴到最近关键帧"（lossless.py `_snap_in`）；关键帧越密 → 切点偏差越小 → `no_kf`/`kf_far` 警告越少 → 无损越稳、画面增减越少。
- 代价：关键帧越密 → 副本文件越大、统一转码略慢、但**剪辑导出这一步更快更稳**。

这就是"把慢的一次性重编码放到统一阶段，换剪辑每次秒级"的取舍核心。当前默认 2 秒是均衡值。

## 四、参数充分性结论（针对"快速导出"目标）

| 参数 | 对快速导出的作用 | 是否建议改 |
|---|---|---|
| 视频编码（H.265 8/10bit） | 决定副本编码；同档才规格一致 | 不动，标红正确 |
| 音频码率 | 不影响拼接（AAC/48k/声道是自动统一） | 可考虑降级标注，非必须 |
| 关键帧间隔 | **直接决定关键帧密度→无损下刀精度/稳定性** | 唯一值得为"剪辑"优化的项 |
| 码率质量 CRF | 只影响画质/体积，不影响能否无损 | 不动 |

**结论：现有 4 项对"能快速导出"已经够用**，闭环已通。若要进一步优化剪辑体验，唯一有意义的调整是**关键帧间隔**：为"以剪辑为主"的用户提供更密的关键帧（如默认 1 秒或新增 0.5 秒档），代价是副本体积增大、统一转码变慢。其余项无改动价值。

## 五、可选的改进方向（供用户决策，均未做）

1. **关键帧策略优化（最贴合目标）**
   - a. 把默认 `keyint_sec` 从 2 秒改成 1 秒（关键帧加倍密，切点更准）——影响所有用户，改动小（改 `CODEC`/默认 + 探针断言），但副本变大。
   - b. 在 1/2/4 之外新增「0.5 秒（剪辑优先）」档，让用户按需选——不动默认值，最安全，改动中等。
   - c. 加一个「用途=剪辑」的预设，一键设成密关键帧 + 高质量档——改动较大，需 UI 空间（顶栏参数条已紧凑）。
2. **音频标红口径**（上一轮已提）：降级为橙/灰或改文案「音频码率(音质)」。与快速导出无直接关系。
3. **不动**：维持现状，靠现有默认已能秒级导出。

**我的倾向**：若用户确实"统一主要是为了剪辑快速导出"，推荐 **1b（新增 0.5 秒剪辑优先档）** 或 **1a（默认改 1 秒）**——这是唯一真正影响剪辑体验的杠杆，且改动可控。1c 改动大、顶栏空间紧张，非必要不做。

## 六、改动的约束/护栏（动手时必须遵守）
- 顶栏参数条 `NormParamSlot` 用确定性缩放（v228），加选项要重新验宽度不重叠。
- 档位是单一来源：`normalize_profile_current`，`NormProfile.from_dict` 有白名单校验（KEYINT_CHOICES），加档要同步改 `KEYINT_CHOICES`。
- 副本指纹含档位（`profile_key`），改档位选项会让老副本失效——属预期，但要让用户知道。
- 判定/探测/导出三处都走副本 resolve，任何改动都不能破坏这个一致性。
- 改完必走：verify 新脚本 + 全量回归（基线仅 5 个长期 safe-delete）+ 打包部署 + 标题验收。
