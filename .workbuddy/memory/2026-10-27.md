## v119（无损剪辑：判定 + 实时告知 + 导出）

用户原话：「我想做的是无损剪辑，如果这个过程中是有损（和传统剪辑软件一个原理，切剪辑速度很慢的那种）的必须告知“不建议剪辑”」。四个关口问完定死：**一做就提醒 / 能导出但必须先看警告 / 切点自动贴最近关键帧 / 重叠直接判不建议**。

- **判定内核 `core/lossless.py`**：`evaluate(timeline, specs, ffmpeg_ok) -> ExportPlan`。三档 `fatal / warn / info`：
  - fatal（→「不建议剪辑」）：跨轨重叠、图片素材、倍速≠1、音频与视频混排、视频规格 signature 不一致、没有 ffmpeg。
  - warn（仍可无损）：中间有空隙（会被吃掉）、静音段（音轨要重新生成）、没读到关键帧、入点偏移 >2 秒。
  - info：入点自动贴关键帧的偏差秒数。
  - 同时产出 `segments`（已按时间排序、入点已吸附关键帧），导出直接用，不二次判定。一键修复 `apply_fix(code)`：compact / demute / reset_speed / drop_image / drop_audio / separate。
- **⚠️ 跨轨重叠不能用 `free_slot` 修**：free_slot 只看同轨。`separate` 改成"按时间顺序往后推（起点不早于前段终点），推完再在同轨避让"。
- **导出 `merge/export.py`**：无损 = 每段 `-ss/-t -c copy -avoid_negative_ts make_zero` 切出来 → concat demuxer 拼；静音段视频照样 copy、音轨用 `anullsrc` 现生成（只有音频重新编码）；转码 = 一条 `filter_complex`（黑底 + 每个片段 scale/pad/setsar/fps/setpts + overlay enable=between + adelay/amix），保留时间轴布局（空隙黑屏、重叠合成）。
- **界面**：工具条右侧胶囊（✓ 可以无损 / ! N 处要注意 / × 不建议剪辑，点开原因清单）+ 不能无损时顶部挂红色横条（不弹窗，免得打断拖动）+ 时间线片段红/黄描边和右上红角 + 导出按钮。`LosslessDialog` 一个类两种用法（readonly=看原因/带路径=导出），非无损时导出按钮写成「仍要转码导出（慢 · 画质有损）」红底。
- **剪辑态探测顺带补全规格**：`ClipProbeWorker` 以前只回 duration/keyframes，现在把 `spec` 一起带回并写进 `merge_specs` —— 否则剪辑态现加的素材没有规格，判定只能一直说"还没读完"。

### 踩坑（都很值钱）
1. **验证"有没有重编码"不能用 `-f md5`**：它把时间戳/封装一起算进去，copy 出来的片子 md5 也会变（时间戳被 make_zero 改过）。**逐像素按秒取帧也不行**（seek 落到不同帧，testsrc2 差一帧就完全不同）。
   → 正确做法：`ffprobe -show_data_hash md5 -show_entries packet=data_hash`，比对**包级 payload 哈希**。实测 copy 结果与源前 20 个包逐字节相同；concat 时**每段第一帧**会因参数集挪到文件头而变，比对时跳过它。
2. **纯色素材证明不了任何事**：`color=red` 重编码后像素也一样。测试素材必须用 testsrc2 / smptebars，并做一组"重编码对照"（重编码后包必然不同）才能反证。
3. **copy 裁剪有 GOP 边界精度**：`-t 2` 实际切出 2.08 秒（52 包）/ 拼接 4.0 → 4.21 秒。这是无损剪辑的固有特性（LosslessCut 一样），断言容差要留 ±0.3~0.4 秒。
4. **`Timeline.place` 会避让**：把多个 Clip 一次性 `clips += [...]` 再逐个 `place()`，因为未摆放的片段默认 `start=0`，第一个就会被挤到别处（测试里 gap 算成 1.0 的真凶）。测试构造要"append 一个 → place 一个"。
5. **QSS 不认 `#RRGGBBAA`**（8 位 hex 被丢成无效值，底色变实心）→ 半透明一律 `rgba(r,g,b,a)`。
6. **`✕`(U+2715) 微软雅黑没字形**，QLabel 里画成方块 → 统一用 `×`(U+00D7)。
7. `Plan.total` 两套语义：无损=去空隙后的累加；转码=时间轴最晚结束（重叠不累加）。

### 验证

## v120（v119 交付后回看：补两个「点了导出却导不出来」的真 bug）

v119 判定/界面都对，但真跑一遍发现两类素材**点导出必定失败**，属于食言（界面说能导 / 能转码，实际一句 ffmpeg 报错）：

1. **静音段 100% 切不出来**。`_cut_cmd` 把 `-map 0:v:0` 插在第二个 `-i`(anullsrc) 前面 → ffmpeg 报 `Option map cannot be applied to input url anullsrc`。根因是**ffmpeg 位置参数规则：所有 `-i` 必须先写完，再写 `-map`**（选中哪个流的选项一旦出现在下一个输入前，就被当成那个输入的选项）。
   - 修完顺带确认：静音只重新生成那几秒的音轨，**画面仍是 copy**（包级哈希逐字节一致，测试钉住了）。
2. **一段有声音、一段没有 → 转码路径崩**。`_reencode` 无条件给每个输入加 `[{i}:a]` 滤镜，无音轨的素材没有这条流 → 整个 filtergraph 报 `Stream specifier ':a'`。修：只对**确实有音轨**的输入引用。

### 判定文案和兜底
- 「有的有声音有的没有」原来只由 signature 笼统报成"音频编码：aac ≠ —"，没人看得懂 → 单独一条 `audio_presence` 讲人话。⚠️ **连带坑**：有无音轨会同时改 5 个 fatal 项（audio_codec/sample_fmt/sample_rate/channels/**nb_streams**），只剔音频四件套的话 "流结构 2 ≠ 1" 会让它再列一遍 → 5 项全剔。
- 无损失败不再只弹「导出失败」：错误统一加「无损拼接没能成功：」前缀，UI 识别后给台阶「改用重新编码导出（慢 · 画质有损）」，默认焦点在「算了，不导了」。
- `export()` 判断顺序修：**先判 blocked/没 ffmpeg 再判没片段**（反了会对"没装 ffmpeg"的人说"时间线上还没有片段"）。

### 兼容性矩阵（实测都过）
都有音轨 / 全无音轨 / 一段静音 / mp4+mov / mp4+mkv / 一段有声音一段没有（转码）——6 种组合全部能导出。

## v122（剪辑页工具箱：改帧率/削减/波形/检测/修时长）

### 核心（`core/media_tools.py`，全部真 ffmpeg 实测通过）
- **改帧率 = 无损变速**：`-itsscale 1/speed -i in -map 0 -c copy`。25fps→50fps：时长减半、`avg_frame_rate` 变 50、**视频包逐包 md5 一致**（真无损）。
- **大幅削减（LosslessCut 的 Decimate）**：`-discard nokey -i in -c copy -bsf:v h264_mp4toannexb -f h264 kf.raw` → 再 `-r out_fps -i kf.raw -c copy out.mp4`（裸流重封装才能把时间戳压平）。every>1 时逐帧抽 `.h264` 再二进制拼接。只支持 h264/hevc；输出无音轨。
  ⚠️ 直接 `-discard nokey -c copy out.mp4` 帧数对了但**时长仍是原长**（时间戳没重排）。
- **波形**：`-map 0:a:0 -ac 1 -ar 2000 -f s16le -` → `proc.run_bytes`（新加，proc 只有文本版）→ `struct.iter_unpack("<h")` 按桶取峰并拉满。
- **检测**：blackdetect / silencedetect / `select='gt(scene,0.35)',metadata=print`；`-progress pipe:1` + `stderr=STDOUT` 合并读，边读边报进度可取消。
  ⚠️ **blackdetect 把 start 和 end 打在同一个行**（`black_start:0 black_end:2`）→ 看到 start 就 return 会永远读不到 end，整段被判黑场。
  ⚠️ `-f null -` 会和 `-progress pipe:1` 抢 stdout → 改用 `os.devnull`。

## v125 —— 「添加」弹窗拉框彻底重查（用户报：老问题没解决 + 出现两个框）

### 真正的三个根因（v124 只修了表面）
1. **`model.rowCount()` 恒等于 1**：`_FileListView`/`_FileTreeView` 都是
   `setRootIndex(文件夹)` 的"以文件夹为根"视图 → 顶层 rowCount()=1，真正的行数在
   `model.rowCount(self.rootIndex())`。v124 的 `_mq_select` 按 `rowCount()` 遍历 →
   每次只检查一行 → **拉框一个都选不中**（框会画、会跟着滚，但选不上）。这就是
   "旧的问题没解决"。修：遍历一律 `model.index(r, 0, root)`。
2. **滚动值不等于像素**：`QTreeView`（详细信息）是按**行**滚的，`vbar.value()` 是行号；
   而 `QListView`（大图标）虽然 `verticalScrollMode()` 也报 `ScrollPerItem`，实际却按
   **像素**滚。按 mode 分支必错一边（踩过：乘行高 → 偏移 ×150 → 框直接拉到 12000px）。
   修：`_mq_bar_px()` 用"第 0 行的 `visualRect().top()`/`left()` 反推"偏移，两种视图都准。
3. **两个框 = 我们的 Marquee + Qt 自带橡皮筋同时跑**：按在**条目上**再拖（大图标很常见），
   `_mq_press` 返回 False 交给 Qt，之后 `mouseMoveEvent` 里又 `super()` → Qt 自己起一个
   橡皮筋（QSS 下画成淡色底、且**不跟滚轮**），我们那个蓝色框也在 → 屏幕上两个框。
   修：**左键按下期间所有鼠标移动都由 `_mq_move` 吃掉**（`return True` 不调 super），
   Qt 的橡皮筋就再也没有机会出现；`_mq_press` 进来先 `_mq_teardown()` 清残留。

### 另外两个坑
- **多列视图 visualRect 只有第一列宽**（100px）：框拉在右边永远打不中 → 多列时按整行宽算。
  判断"是不是多列视图"不能用 `columnCount`（文件模型恒为 4），要看
  `visualRect(index(0,1)).isValid()`（大图标视图第 2 列没有可见矩形）。
- **网格换行时行号不是按 y 排的**：`indexAt(左上角).row()` 当起点会跳过它上方同屏的其它列
  （5 列时跳过 4 行）。`visualRect().bottom()` 随行号单调不减 → 起点用**二分**找
  （`_mq_first_row`），几千个文件也不会每次从第 0 行扫。
- 树视图 `setMouseTracking(True)`：关着时"没按键的移动"根本送不到视图，万一松手事件丢了
  （在窗外松手）就没机会收掉残框。`_mq_move` 里"按着左键的通知却收到无键移动"= 松手丢了 → 立刻收框。

### ⚠️ 本次最深的坑：掐声之后进程随机崩
现象：跑验收脚本时，声音测试之后**在完全不相干的 `import` / `enum` 里
access violation**。二分（probe_audio2/3）结论：
- A 只开/关声卡、B 直接 WaveOut 播完 → 都不崩；
- **C 中途 `stop()`（掐 ffmpeg + 跳过 drain + 直接 close）→ 必崩**；
- C2 自然播完 → 不崩；C4 换成 threading.Thread 也崩 → 与 QThread 无关。
根因：`waveOutReset` 只是"请求"驱动归还缓冲区，**DONE 不是立刻置位**；
不等 DONE 就 `waveOutUnprepareHeader` + 释放 ctypes 缓冲区，
驱动会往已回收的内存里写 → 之后随机崩。
修法（两条一起）：
1. **一条常驻线程 + 一张常开的声卡**：`SoundPlayer`（常驻 QThread，覆盖式任务
   `_job` + 代号 `_gen` 顶掉旧段；`silence()` 只 reset 不关不重建；`stop()` 才退出并 close）。
   绝不"播一段 new 一个线程 + 开一次声卡"（拖进度条一秒好几次，既违反线程铁律又踩开关雷区）。
2. `WaveOut.reset()`：reset 之后**轮询等到 DONE 再 unprepare**；
   `close()` 若关不掉就**不释放**缓冲区（宁可泄漏几十 KB，也不能让驱动写野指针）。

## v138（轨道缩略图提速：放大 4.9 倍 / 全览 2.2 倍）

用户一句话："轨道上缩略图显示慢 / 缩放后不能及时显示"。**先量再改**，测出来两根慢的方程：

### 实测数据（1080p 30fps 素材，`out/repro/_big.mp4`）
- 单独抽一张：**约 110ms**（大部分花在起进程 + seek）
- 一次 ffmpeg 连抽 12 张：**每张 16ms**
- 端到端"一屏从空白到填满"：放大 1608ms → **330ms**；全览 1177ms → **533ms**

### 1. 一次 ffmpeg 连抽多张（大头）
- 用 `select` 精确定点。`-vf "select='between(...)+...',scale=160:-2" -fps_mode vfr`
- ⚠️ **select 里的 `t` 是相对 `-ss` 起点算的**（ffmpeg 9 实测）。不减 seek 起点会抓错帧；
  减掉之后与"单独抽那个时间点"**像素完全一致**（验收里逐像素比，最大差 < 3）。
- ⚠️ **必须加 `-frames:v N`**：不限张数的话 ffmpeg 会把**整段解到文件尾**才收工
  （实测 5 张从 1660ms 掉回 140ms —— 第一次做出来比单抽还慢，就是漏了这一条）。
- ⚠️ `-vsync` 在 ffmpeg 9 已改名 **`-fps_mode`**（写 `-vsync` 直接报 Unrecognized option）。
- ⚠️ 张数对不上就**整批作废**退回逐张抽：select 命中数稍差一点，后面所有帧就整体错位，
  宁可慢也绝不给配错时间的图。
- ⚠️ **一簇的"总跨度"必须封顶**（CLUSTER_SPAN=8s，相邻间隔 CLUSTER_GAP=2s）：
  缩到看全貌时相邻格子隔着十几秒甚至几分钟，硬凑一簇等于把中间几十分钟全解一遍，
  比一张张 seek 慢得多。解 1 秒 1080p 约 70ms，所以 8 秒封顶 ≈ 0.5 秒一批。

### 2. 抽帧从"单线程串行"改成"线程池 + 共享心愿单"
- `FilmstripWorker` 不再是 QThread，改成 QObject 管理器（对外还是 start/stop/request/
  wait/frameReady，main_window 一行没动）；里面 3 条 `_StripThread` 共用一张 `FrameWishlist`。
- 心愿单：`(源, 量化时间)` 去重；**按源轮转**取活（几个片段同时往前长，长片段不会堵死别人）；
  一次取"一簇"正好喂给 `extract_batch`。
- 线程数是按核数给的（≥8 核给 3 条）。抽帧是 ffmpeg 子进程在干活，Python 这边只是等，不必多给。
- 空闲轮询 70ms → 20ms（第一张图不用等到发慌）。

### 3. 量化粒度跟着缩放走（STEP_LADDER）
- 原来固定 0.5 秒。现在按"一格代表多少秒素材"取阶梯档位：
  `0.5 1 2 5 10 30 60 120 300 600`。
- 用**固定阶梯**而不是直接用 span：相邻几个缩放级别会算出同一个键 → 来回滚/微缩放能命中缓存。
- ⚠️ `on_frame` 里**不能再 quantize 一次**（两次浮点运算未必逐位相同 → 键对不上 = 白抽）。
  键统一在 paint / wishlist 两边用同一个 `FS.quantize(t, step)` 算。

### 4. 缩放/滚动后丢掉过期需求
- `TimelineWidget._film_drop_stale()` → `worker.clear_pending()`；挂在 `set_pps` 和
  `hbar.valueChanged` 上。不然线程还在抽"早就滚出屏幕"的那些帧，眼前的却排在队尾。

### 5. 顺手修的两个老毛病
- 内存缓存满了**整个 clear()** → 改成丢最旧 1/4（来回滚时不用全部重抽）。
- 抽不出来的时间点（最后那一格常常正好落在文件末尾之外）会每次重绘都去起一个注定失败的
  ffmpeg → 记进黑名单 `_dead`；同时 `_paint_filmstrip` 里超过素材时长就不再请求。
