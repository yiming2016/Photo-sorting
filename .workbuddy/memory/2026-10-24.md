## v74 — 「读取失败：ffprobe 返回码 0」真凶 = GBK 解码 UTF-8；黑窗消除；删关闭按钮

用户两条：① 删掉 FFmpeg 设置页的「关闭」按钮；② 所有视频都显示"读取失败：ffprobe 返回码 0"，且**弹出 cmd 窗口一闪而过**。

### 真凶（实测复现，不是猜的）
在源码环境里 probe 一切正常（中文名、特殊字符全过），但打成 `--windowed` 的 exe 后**必错**。
用 `out/repro/probe_repro.py` 打了个 7 秒的迷你 windowed exe 复现，日志（末行是关键）：

```
sys.stdout: <_io.TextIOWrapper name='<stdout>' mode='w' encoding='gbk'>
raw probe rc: 0 | stdout len: 0 | stderr: ''
probe_ex: (None, 'ffprobe 返回码 0')

Exception in thread Thread-2 (_readerthread):
UnicodeDecodeError: 'gbk' codec can't decode byte 0xad in position 3569
```

即：`subprocess.run(text=True)` 在中文 Windows 上按 **GBK** 解码子进程输出，而 ffprobe 输出的是 **UTF-8**（`-show_format` 的 json 里含中文文件名）→ 读取线程抛 `UnicodeDecodeError` → **stdout 空、returncode 仍为 0** → 我们的分支只能报"返回码 0"。
源码环境测不出来是因为工具环境开了 UTF-8 模式（`getpreferredencoding()` 返回 utf-8）。
推论：**只要文件名带中文就必错** → 用户所有视频全红，完全对得上。

### 修法
1. 新增 `app/merge/proc.py` 的 `proc.run(cmd, timeout)`：`encoding="utf-8", errors="replace"` + `stdin=DEVNULL` + `CREATE_NO_WINDOW` + `STARTUPINFO(SW_HIDE)`。
   - 编码修的是空输出；`CREATE_NO_WINDOW` 修的是**黑窗一闪**（--windowed 进程无控制台，Windows 会给控制台子进程新分配一个）。
2. `probe.py` / `merge_run.py` / `ffmpeg_settings._run_version` 三处 `subprocess.run` 全部换成 `proc.run`。
3. `probe.py` 增加 `log_line()`：失败时把 rc / stdout 长度 / stderr 前 400 字写到 `%TEMP%\photosort_merge.log`；空输出时的兜底文案改为"ffprobe 返回码 N，但没有输出任何内容"。
4. `ffmpeg_settings.py` 删掉底部「关闭」按钮（只剩标题栏 X 关闭），对话框高度 235→190；`QHBoxLayout`/`QVBoxLayout` 仍在用，`subprocess` 导入不再需要（保留未删）。
5. `merge_run.py` 里局部变量改名 `proc_`，避免与模块 `proc` 同名。

## v80（合并模式右键：不再取消选中 / 菜单不再跳错）

### 真因
1. `GroupView.mousePressEvent` 的合并分支**没判断左键**——右键点已勾选的格子走的是"切换勾选"逻辑，
   直接把那格取消掉。取消后 `selected_photos()` 变空，`_show_merge_menu` 就只加"全选同规格/全选所有视频"，
   于是"指着文件右键却弹出空白菜单"。
2. 修的过程中又踩一个坑：为了给「全选同规格」定位而调 `self.setCurrentIndex(idx)`，
   结果**2 选变 1 选**——`QAbstractItemView::setCurrentIndex()` 内部用 `selectionCommand(...)`（无事件时=ClearAndSelect），
   会把多选清成一个。必须用 `selectionModel().setCurrentIndex(idx, QItemSelectionModel.NoUpdate)`。
3. 空白键（右键空白）以前也走原分支：清空选中 + 启动橡皮筋，等于"右键空白就把队列清了"。

### 改法（只动 `grouplist.mousePressEvent`）
- 入口处 `if event.button() != Qt.LeftButton:` 单独处理并 `return`：
  命中照片 → `sm.setCurrentIndex(idx, NoUpdate)`；未选中则 `ClearAndSelect`（带 Ctrl/Shift 则加选）。
  右键**绝不**取消已选；右键分组标题不再误触勾选框/折叠/年月开关；`_press_index = -1` 防止右键拖拽。
- 合并态左键分支同样改成 `NoUpdate` 挪光标 —— 合并态不调 `super`，光标从来不更新，
  「全选同规格」以前只能退化成"已选第一段所在组"。

### 验证（`out/t_v80g.py`，两组规格 640×360 / 1280×720）

## v94（合并参数审查：fatal 对齐 signature + 时间基 + 属性窗口补齐）

### 用户
仔细检查 FFmpeg 合并相关，尤其「必须一致/建议一致」是否出错、有无遗漏（如 time_base），
覆盖属性/对比/右侧参数对比/主页面显示；模糊就问。

### 审查发现
1. **真 bug：fatal 档与 signature() 硬门槛不一致**。signature 一直把
   分辨率/帧率/采样率/声道数/流数量当硬门槛（不一致就分不了"可无损"组），
   但 FIELD_LEVELS 把它们标成 warn/None → 分组说不能无损、对比窗口只标橙，自相矛盾。
2. time_base 完全没采集。
3. 属性窗口视频/音频页漏了 v92 新增的字段（v92 只改了对比/右侧，_fill_video 没跟上）。
4. 主界面标题 7 项缺 采样率/声道数/流数量 3 个致命项（问了用户，答"补上"）。

### 修复
- **fatal 档 11 项 = signature 11 个硬门槛**：width/r_frame_rate/sample_rate/channels/
  nb_streams 升级 fatal。分档与判定从此一一对应（grouping.py 里留了注释警告：
  以后改 signature 必须同步 FIELD_LEVELS）。
- probe 采集 `video.time_base`，FIELD_LEVELS 加 ("time_base","时间基","warn")
  （concat demuxer 能重排时间戳，通常不失败 → 建议一致档）。
- `_fill_video` 补 7 行：bits/level/field_order/time_base（视频）、audio_profile（音频）、
  nb_streams/format_name（其它）；颜色由 _SPEC_LABEL_COLORS 自动派生。
- 展示值人性化（field_value，四处同步）：`_sample_rate_text` 48000→48kHz/44.1kHz、
  channels→"2声道"、nb_streams→"2流"。signature 用原始 spec 值不受影响。
- HEADER_FIELDS 7→10：video_codec/pix_fmt/audio_codec/sample_fmt/sample_rate/
  channels/nb_streams/color_transfer/width/r_frame_rate。
  分组标题里 分辨率/帧率 从橙变红（现在它们是 fatal）。

### 验证
- `out/t_v94_audit.py`：11 个硬门槛→fatal 全映射；time_base=warn 可显示；
  只有分辨率不同→分辨率红/其余绿；只有帧率不同→帧率红；probe 含 time_base；
  _fill_video 含 7 个新 key；HEADER_FIELDS 10 项。
- 截图 `out/v94_compare.png`：必须一致档(红标题)含 分辨率/帧率/采样率 + 一致绿项，
  建议一致档(橙标题)含 编码档次/编码等级/音频档次/扫描方式/时间基。
- 发布：__build__ 93→94，exe 标题 `照片排序台 v94`（PID 11820）。
