# v167 —— 音频也走「帧率/倍速」/ 音频片段显示倍率 / 修带音频导出 / 快捷键冲突红字

## 用户原话
> 做音频，"帧率/倍速"这个按钮同样也要可以修改选中的音频片段(只是修改和显示内容不同)，音频片段的末尾时间下面也要显示当前倍率。
> 快捷键的设置，如果录入的时候想设置的快捷键和已有的冲突，要红字提示和哪个冲突，并且不能被录入(点击保存按键)

## 改了什么
### 1) 「帧率/倍速」对音频开放 (`clip_editor.py` + `main_window.py`)
- `_sync_tool_buttons(has_video, fps, speed, has_audio=False)`:
  「对齐关键帧 / 精简 / 检测」仍然只认视频; `fps_btn` 视频或音频都能点。
  文字: 视频 "45/1.3"; **音频只有倍速 "1.5"**(没有帧率这一半)。
- `set_fps_label(fps, speed, audio=False)` 加音频分支; tooltip 写「音频倍速（导出时重新编码，音调不变）」。
- 两处调用点(`_after_edit_changed` / `_on_edit_clip_selected`)都改成读 `selected_clip()` + 传 `has_audio`。
- `_tool_change_fps`: 音频分支 → `_tool_change_audio_speed(clip)`。
- **`_tool_change_audio_speed` 不生成新文件**: 直接把 `clip.speed` 记在片段上(原文件一字节不动,
  可再改/可撤销), 时长自动按 `(src_out-src_in)/speed` 缩放; `tl.place()` 防同轨撞上, 磁吸开就整轨合拢。
  这是和视频刻意分开的: 视频变速 = 挪时间戳(无损), 音频没有帧只能导出时 atempo 重编。
- 新增 `tools_dialog.AudioSpeedDialog`: 只有倍速一格 + 0.5/1/2/4/8 快捷键 + 时长预览
  (预览按**当前倍速下的时长**算: before = 源长/旧倍速); 值没变时「应用」灰着。

### 2) 片段末尾显示倍率 (`timeline.py::clip_info_text`)
- 音频: **永远**显示 `1× / 1.5× / 1.511×`(1 倍也写, 用户要"显示当前倍率")。
- 视频有帧率: `120fps/1.511×`(照旧); 视频没帧率: 只在变速时写 `2×`, 1 倍不写。

### 3) ⚠️ 带音频片段的时间线导出**以前根本导不出来**(v167 顺手修)
- 真因: `merge/export.py::_reencode` 给每个段都建 `[{i}:v]` 画面链 —— 音频文件没有视频流,
  ffmpeg 直接 `Stream specifier ':v' matches no streams`。而且音频段的 `[i:a]` 又被
  `_has_audio(specs.get(src))` 挡掉(音频根本进不了 merge_specs) → 以前"有音频就必失败"。
- 修: ① 音频段不建画面链, `vsegs` 只收真有画面的段(overlay 循环按 vsegs 对齐, 不能再用 segs[i]);
  ② 音频段一律当"有音轨"处理 → 建 `atempo` 链。
- 另: **纯音频时间线**以前会走"无损"那条路(只切视频流) → `lossless.evaluate` 加 `audio_only` FATAL
  (条件 `auds_all and not visual`, 图片+音频不重复报), 输出 = 黑画面 + 声音。
- 实测: 视频+音频 / 音频 1.5× / 纯音频 三种都能导出, 产物有 aac 轨。

### 4) 快捷键录入冲突 (`edit_shortcuts.py`)
- `_KeyCaptureDialog` 收 `occupied: {规范化键: 占用者名字}`, 录入时**当场**:
  大字与提示改红字「已和「播放 / 暂停」冲突，换一个键才能保存」, 捕获框边框变红,
  **「保存」按钮点灰**(回车走 `_accept` 也拦)。换一个不冲突的键就恢复, 清空也能存。
- `_begin_capture` 组装 occupied 时**排除正在改的这一格**(含同动作的另一个槽要算占用);
  主面板原来那段"事后提示"保留作双保险。
- 测试注意: 假录入窗要接 `occupied=None` 形参(v142 已同步)。

     props_dialog._ProbeWorker), 参数名按致命度标色(红 fatal / 橙 warn / 灰其它),

  使用方式两档(自动优先本地 / 仅用本地指定) + 只读路径行 + 来源标注 + 检测(跑 -ver) +
  **一键更新** + 获取 ExifTool… + 清除自定义 + 更新日志(平时隐藏)。
- 设置键: `merge.json` 的 `exiftool_path`(exe 完整路径, 不是目录) + `exiftool_mode`。
- `core/exiftool.py`: `find_exiftool(mode=None)` = 自定义(存在则用) > 自带 tools > PATH > 常见目录;
  MODE_LOCAL 没自定义 → None。新增 `refresh_exiftool()` 关常驻进程让下次按新路径重启。
- ⚙ 菜单顺序: 参数分档 → **ExifTool 路径 / 更新…（已就绪）** → FFmpeg 路径 / 检测…;
  `MergePanel.exiftoolRequested` → `main_window.open_exiftool_settings()`。

## 一键更新的下载源（关键，别再试 exiftool.org 直链）
- exiftool.org 的下载链接全指 SourceForge → Cloudflare 人机验证，urllib/curl 一律 403。
- 改走 Oliver Betz（exiftool.org 官方 Windows 包自 2024 起就用他的启动器）:
  `https://oliverbetz.de/cms/files/Artikel/ExifTool-for-Windows/`
  - 版本号: `exiftool_latest_version.txt`（纯文本，如 13.61）；失败退回解析 exiftool.org 首页 `Version x.yz`
  - 包: `exiftool-<ver>_64.zip`（13MB，含 `ExifTool.exe` + `exiftool_files/`，与自带结构一致）
  - 只需要加浏览器 UA，无其他鉴权。
- 装法: 解压 → 关常驻进程 → **旧 exiftool_files 先改名成 `.old`（不能直接 rmtree，否则可能留半新半旧）**
  → 搬新 files → `os.replace` 换 exiftool.exe（失败则回滚）→ rmtree(.old) 失败也不管。
  用户指定过自定义 exe 就更新到那份所在目录，并把路径改指新的 exiftool.exe。
- 替换前 `_kill_holders()`: 用 WMI 查进程里 ExecutablePath **等于**目标 exe 的杀掉
  （程序崩溃留的孤儿常驻进程会锁 exe → WinError 5 拒绝访问）。只杀这个路径，不碰别的程序的 exiftool。
- 自带 exiftool 顺带升到 13.61（源码 tools/ 与打包 _internal/tools 都是）。
