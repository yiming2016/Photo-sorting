## v140（四条：素材框按勾选 / 裁剪线吸附 / 右栏片段清单 / 快捷键双键位）

用户一次提了四件事，前面问清了三个口径：**没勾就空着**、**右侧只放清单(属性继续收着)**、
**拖动 = 改轨道上的先后顺序**。

### 1. 合并页没勾选的文件不进剪辑素材框
- 素材框原来是 `model.photos` 全量。合并页的"勾选"其实就是**主列表的选中项**
  (`view.selected_photos()`), 不是 `Photo.merge_checked`(那个字段只属于 HeaderRow 的组标题勾选框)。
- 进剪辑时记一份 `_edit_allowed = {canon(path) ...}`, `_refresh_media_panel` 里过滤;
  剪辑里现加的素材(`_edit_extra`)不受限。一个都没勾 → **素材框空着**(用户明确要这个, 别兜底显示全部)。
- ⚠️ 每次 `enter_edit()` 都重取一遍: 用户可能回合并页改勾选再进来。

### 2. 裁剪线吸附(v139 之前根本没有)
- `_set_playhead_x` 原来是纯像素换算。现在差 8px 以内贴到 `snap_targets(include_playhead=False)`:
  片段首尾(= 两个素材的接缝 / 素材顶端末端) + 每条轨 0 点。拖动时画紫色吸附线。
- ⚠️ **绝不能用 `timeline.snap()`**: 它把播放头自己也当一个吸附点 → 裁剪线一拖就粘在原地,
  松手弹回去, 表现成"怎么拖都动不了"。必须显式 `include_playhead=False`。
- 跟「磁吸」开关走(`snap_on`), 关掉就不吸。
- 松手(`_scrub` 结束)要清 `_snap_line`, 否则紫线留在那儿。

### 3. 右栏轨道片段清单(`app/ui/clip_list.py`, 新文件)
- 右侧那块原来一直是**空的**: `clip_editor.py` 里 `self.panel.setVisible(False)` 之后没人打开过。
  现在整块给片段清单, 属性面板继续收着。
- 一个片段一张卡片: 序号 + 缩略图(等比铺满+居中裁切) + 文件名 + `时长 · 第 N 轨`。
  自绘 delegate(`QListWidget::item` 的 QSS 会吞背景, 选中态看不出来)。
- 点卡片 → `timeline_view.select_clip()` + `clip_editor.set_playhead(clip.start)`
  (后者会 emit `playheadMoved` → 预览跟着换)。
- 拖动 = `InternalMove`; `rowsMoved` 里**只按 item 上存的 `id(clip)` 反查**新顺序,
  不要用 start/row 算边界(不同 Qt 版本"插前还是插后"不一致)。
- 重排规则: 第 i 个位置**沿用原来的轨道号**, 只换内容(轨道数不会变多);
  每条轨道还从原来最早的起点开始, 之后首尾相接。
- ⚠️ 刷新时若 `list.state() != NoState`(正在拖) 就直接跳过, 不然会把用户手里的卡片抽走。
- 撤销会重建 clip 对象 → 每次结构变化都整表重建(靠 id 对不上自然重来)。

### 4. 快捷键一个动作两个键位
- `bindings` 值从 `str` 变成 `[主键, 备用键]`。新增 `as_slots(val)` 统一兜底:
  **旧配置是字符串, `for seq in v` 会逐字符遍历** —— 必须走 as_slots。
- 录入窗改成**两个模块**(主键 / 备用键), 点哪块录哪块; `result_slots()` 返回两个值。
  角标 QLabel 一开始忘 `addWidget` → 界面上看不到"主键/备用键"。
- 主面板从"一行两列"改成"一行一个动作": 说明 + 两块键位。
- 冲突检测跨**所有动作的所有槽**: 两个槽都跟别人撞就拦; 同一动作另一槽也拦。
- 注册 QShortcut 时每个槽各建一个, 用 `seen` 去重(同一个键注册两遍 = Qt ambiguous, 两个都不响应)。
- 默认备用键全部留空(不凭空塞键位)。

## v143（合并界面点组标题小三角收不起来）
用户原话：「“排序”主界面，添加进去的文件无法点击左侧收起所包含的文件」→ 追问后更正：「输错了，是合并界面」。

### 根因
- 主列表有**两套**铺行算法：排序 `rebuild()`（按年/月/日，读 `self.collapsed`）、
  合并 `_rebuild_merge()`（按规格分组，**不读 collapsed**）。
- 所以合并界面点三角：`hit_test_header` → "collapse" → `toggle_collapse()` 把键记进
  `collapsed` 并 rebuild，可 `_rebuild_merge()` 照样把成员全列出来 → 看着"点了没反应"。
- 先按用户说的"排序界面"排查时怎么都复现不出来（四种场景都正常）— 这正是纠错的价值：
  **用户说的界面不一定是要改的那一处，先复现、复现不出来就问。**

### 修
1. `_rebuild_merge()` 读 `key in self.collapsed`：标题行带 `collapsed`，收起时 `continue` 不列卡片。
2. 合并顶栏「共 N 段视频」改成数 `model.photos` 里的视频（原来数行列，一收起数字就变小，
   看着像文件少了几段）。收起只是"不显示"，文件还在（和排序界面一致）。
3. `enter_merge()` 里 `model.collapsed.clear()`：每次进合并是一次新分组（规格签名会变），
   上次收起过的不作数，免得"一进去就像这组是空的"。
4. `hit_test_header` 三角命中范围往四周放 6/8px（16×16 → ~28×32）—— 用户抱怨"点三角没反应"，
   有一半是差几个像素没点准；右边界不能越过 `text_left`（那里是「全选本组」勾选框）。
   「点在标题文字/空白处什么都不做」这条**保持不变**（没改成整行可点）。

## v145（排序页年份前全选勾选框 / 剪辑左右互斥 / 右栏 Del + Ctrl+Z）

用户提的三条：
1. 「排序」界面年份前面也要有一个能全选的 ✅（截图里 `▼ 2026 年`）；
2. 剪辑页不允许同时选中左侧素材和右侧片段；
3. 右侧片段上按 Del「删除素材」之后 Ctrl+Z 这类按键没生效。

### 查到的真根因
- ③ 不是快捷键失灵，是**删错了东西**：右栏片段清单是 `NoFocus`（空格要留给播放），
  点卡片不会把焦点从素材框抢走 ⇒ 原来 `edit_delete` 按「`media.list.hasFocus()`」分流，
  于是按 Del 删的是**素材框里早先选中的那个素材**（片段一动不动），而「移出素材框」

### 改法

  `_remove_media` / `_remove_from_media` 都补 `_edit_commit()`；撤销后补 `_refresh_clip_list()`。
- 左素材 / 右片段互斥：`_preview_media` 先 `_clear_clip_selection()`（撤轨道选中 +
  右栏高亮 + 段内进度条 + 属性/工具按钮）；`_on_edit_clip_selected(clip)` 里
  `media.clear_selection()`（`MediaPanel.clear_selection` 走 `_quiet`，别被当成点了空白）。
- 组标题的勾选框改成**两种形态共用**：`HeaderRow.merge_checked` 改名 `group_checked`，

## v147（分离音频后播放没声音）

用户报：剪辑页「分离音频」之后按播放，一点声音都听不到。

### 根因
播放只认**最上面那条画面轨**：`_play_segment` 取 `tl.top_clip_at(t)`，声音就跟着这一个片段走
（`if not clip.muted: _play_sound(...)`）。而分离音频之后画面那段是 `muted=True` 的、声音躺在
下面那条音频轨上 ⇒ 一路声音都收不到。**不是声卡/ffmpeg 坏了，是压根没把音频轨算进去。**
（附带：`top_clip_at` 本来就跳过 kind=="audio"，所以音频片段永远当不了"画面"，删掉视频只剩
音频时同样没声。）

### 改法
- 新增 `main_window._sound_jobs_at(t)`：遍历**每一条轨**上覆盖 t 的片段，跳过 image、muted、
  没音轨的，各按自己 `src_in + (t - clip_start)` 算源起点 → 返回 [(源, 起, 止), ...]。
  `_play_segment` 三个出口（video / 图片·音频 / 空档）统一用它，不再只看画面那一轨。
- `audio_out.SoundPlayer.request(jobs)` 支持多段：**一路仍走原来那条最朴素的命令**（零风险），
  两路以上才用 `amix=inputs=N:normalize=0` 叠。⚠️ 多输入时 `-t` 必须写在 `-i` **前面**（输入
  选项），写在后面会被当成输出选项 → 只有最后一个输入被截断。
- `_certain_audio()`：混音前必须确认每一路真有音轨（amix 里混进一个没音轨的输入 → ffmpeg
  整条命令报错 → "叠了两轨反而一声都没有"）。缓存里有就用缓存，没有才 ffprobe 一次，
  结果写 `_audio_known`（**不要**写进 merge_specs，那是给无损判定用的，塞半截会带坏判定）。
- `_play_sound` 加签名保护 `_sound_sig`：空隙处播放头每 0.1s 会重走一次 `_play_segment`，
  不挡住就是一秒重启十次 ffmpeg；`_stop_audio` 里清掉。

### 踩的坑（值得记）
**改函数签名必须 grep 全部调用点**：`_play_sound(src, start, end)` 改成 `_play_sound(jobs)` 时
漏了素材预览那两处三参数调用 → `_play_media_preview` 抛 TypeError 被 except 吞成
"播放失败：...takes 2 positional arguments but 4 were given"。表现是 v130「暂停不把位置清零」
（播放头根本没走）。离线脚本看不出来，**只有回归能抓到**。现在签名兜底成
`_play_sound(jobs, start=None, end=None)`，老写法也认。

## v148（分离音频 ≠ 静音, 把这两件事拆开）

用户: 分离音频之后提示"原来的视频被静音了"; 可轨道上的视频声音明明只是被分离出去,
"那就不是静音, 务必理清相关逻辑"。

### 原来的错
分离音频时直接 `clip.muted = True`。于是**到处**都按静音处理:
- 时间线标签写「（静音）」、右栏写「· 静音」、状态栏写"原视频已静音";
- 无损检查报「N 段被静音了」, 还把「取消静音」当修复 —— 一点就变成两份声音;
- 右键菜单变「恢复原音」;
- 无损检查里分离出来的音频落进"音频素材和视频混在一起", 修复是「去掉音频素材」
  —— 一点下去刚抽出来的声音就没了。
语义全错: 静音 = 不要这段声音; 分离 = 声音搬到别处躺着, 一个字节没丢。

### 改法
- `Clip` 新增 `detached`(音轨已分离) 与 `src_parent`(音频片段记着源文件),
  并加 `Clip.silent` 属性 = `muted or detached` —— **"出不声"统一看 silent**,
  "为什么不出声"再看具体是哪个。split_at / snapshot / restore 都带上这两个字段。
- 分离时设 `clip.detached = True`(**不再**碰 muted), 音频片段记 `src_parent`;
  状态栏改成"声音放到下面那条轨了，原视频不再重复出声"。
- 界面: 时间线标签「（音轨已分离）」/「（静音）」分开; 右栏「· 音轨已分离」;
  波形两条都不画(没声音的地方不画波形)。
- 菜单: 分离过 → 「取消分离（声音放回视频）」; 静音过 → 「恢复原音」;
  从没动过 → 「删除原音（静音）」。分离的那段不再给"恢复原音"。
- `_undo_detach()`: 取消分离 = 删掉抽出来的音频片段(走 `tl.remove`, 自动还原)。
- `Timeline.remove()` 里加 `_reattach_audio()`: 删掉分离出来的音频 → 原视频
  `detached` 自动还原。⚠️ 不然"删了个音频文件, 结果原视频彻底没声了, 界面上还
  写着已分离", 看不出为什么。
- 无损检查: 「被静音」只统计真静音; 导出序列里 `Segment.muted = muted or detached`
  (避免和音频轨重复出声)。分离出来的音频**不再**算"外来音频素材", 单独一条:
  「N 段的声音被分离到独立音轨了」+ 修复「取消分离（声音放回视频）」;
  `drop_audio` 也只删外来音频(带 src_parent 的一律不动)。
